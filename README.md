# SplitEasy

A Splitwise-style iOS app:
- Sign in with Apple or Google.
- Groups joined by invite code.
- Expenses in USD, split equally or itemized with **✨ Smart Split**.
- Simplified debts and settle-up.

## Stack
- SwiftUI, iOS 17+, `supabase-swift` (SPM). The Xcode project is generated by XcodeGen from `project.yml`.
- Supabase project `SplitEasy` (ref `eloyohqnvsghwcthfvza`):
  - Schema, RLS and RPCs: `supabase/migrations/`
  - Edge Function: `supabase/functions/smart-split/`

## Run
```sh
brew install xcodegen
xcodegen generate
open SplitEasy.xcodeproj
```
1. **Supabase keys:** `Config/Secrets.xcconfig` (git-ignored) holds the Supabase host and publishable key. On a fresh clone, copy `Config/Secrets.example.xcconfig` and fill it in from `supabase projects api-keys --project-ref eloyohqnvsghwcthfvza`.
2. **Signing:** in Xcode → SplitEasy target → Signing & Capabilities, choose your team.
   - Sign in with Apple needs a paid Apple Developer account and a bundle ID you own (default `com.kaichinh.spliteasy`).
   - If you change the bundle ID, also change `[auth.external.apple] client_id` in `supabase/config.toml` and run `supabase config push`.

## ✨ Smart Split
You describe the expense in your own words and can attach a receipt or screenshot. AI turns that into editable items, and you review everything before it's saved.

```
iOS input (text and/or image)
  → Edge Function `smart-split` {action:"interpret"}
      provider.ts (OpenRouter, the only file that knows the AI provider)
      → schema.ts (strict JSON Schema + zod; unknown people/negative prices are never trusted)
      → calculator.ts (integer cents; the authoritative money math)
      → validate.ts (errors block saving, warnings are shown)
  → iOS review screen (the Swift calculator recomputes instantly on every edit)
  → {action:"commit"}: the server recomputes from the items, then calls `save_expense_shares`
```
- **Three separate layers:** AI parsing, money calculation and persistence. The AI never decides final amounts.
- **How amounts are calculated:**
  - Shared items are split equally.
  - Tax, tip, fees, shipping and discounts are allocated in proportion to each person's item subtotal, using the largest-remainder method.
  - Leftover cents go to the earliest group member.
  - Shares always add up exactly to the total.
- **Where results are saved:** as normal `expense_splits` rows (balances and settle-up are unchanged). The reviewed breakdown goes in `expenses.split_details`, so reopening the expense shows the same items.
- **Model:** `SMART_SPLIT_MODEL` (default `openai/gpt-6-luna`).
- **Rate limit:** 30 calls per user per hour (`claim_smart_split_quota`).

### Turn on the real AI (one-time)
```sh
supabase secrets set OPENROUTER_API_KEY=sk-or-... --project-ref eloyohqnvsghwcthfvza
supabase secrets unset SMART_SPLIT_PROVIDER --project-ref eloyohqnvsghwcthfvza   # turn off the test mock
# optional: supabase secrets set SMART_SPLIT_MODEL=openai/gpt-6-luna-pro --project-ref eloyohqnvsghwcthfvza
deno run --allow-net --allow-read --allow-env supabase/functions/smart-split/eval.ts   # live check of all spec examples
```
`SMART_SPLIT_PROVIDER=mock` switches to a **test-only** rule-based parser (`mock_provider.ts`), used for UI testing without a key. Adding `#fail` to the text makes it return an error.

### Deploy changes
```sh
supabase functions deploy smart-split --project-ref eloyohqnvsghwcthfvza --use-api
```

## Google sign-in (one-time setup)
The app code is done. Until the steps below are finished, tapping "Continue with Google" says it isn't configured yet.
1. **Create the OAuth client:** in [Google Cloud Console](https://console.cloud.google.com/apis/credentials), create an **OAuth client ID** of type **Web application**.
   - Authorized redirect URI: `https://eloyohqnvsghwcthfvza.supabase.co/auth/v1/callback`
   - The OAuth consent screen needs an app name and your support email. Add yourself as a test user while it's in Testing mode.
2. **Save the credentials:** add them to `.env` (git-ignored):
   ```
   SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID=....apps.googleusercontent.com
   SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET=GOCSPX-...
   ```
3. **Turn it on:** set `enabled = true` under `[auth.external.google]` in `supabase/config.toml`, then:
   ```sh
   set -a; . ./.env; set +a; supabase config push --project-ref eloyohqnvsghwcthfvza
   ```

How the sign-in works:
- The app opens Supabase's Google sign-in in a system browser sheet (`ASWebAuthenticationSession`).
- Google sends the user back to `spliteasy://auth-callback`, which is registered in `project.yml` and allowed in `additional_redirect_urls`.
- The user's Google name fills in their profile.

Add a new file in `supabase/migrations/` and run `supabase db push` (the DB password is in `.env`).

## How balances work
- **Splits:** amounts are integer cents. A manual expense's splits are computed in `save_expense` (Postgres): equal shares, with leftover cents going to the first participants. Smart Split expenses use `save_expense_shares` with the calculated per-person amounts.
- **Net balance:** paid − owed + settlements sent − settlements received (`BalanceCalculator`).
- **Simplified debts:** `DebtSimplifier` greedily matches the largest debtor with the largest creditor, which gives at most N−1 payments.
- **Settle up:** "Mark as Paid" records a settlement, which moves balances toward zero.
